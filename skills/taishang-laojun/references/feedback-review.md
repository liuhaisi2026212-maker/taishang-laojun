# 反馈复盘：想要的结果和实际的结果，差在哪一步

柳爷要求的复盘方式是：把“我想达到的目的”和“实际达到的目的”放在一起对比，反推为什么会走向这个结果而不是想要的那个；如果想回到想要的结果，怎么调整；如果已经走到不想要的结果，怎么挽救，或者怎么顺势而为。

复盘要找的是**偏差从哪一步开始**，用不着给视频打分。

## 先分清有什么反馈

- **还没发布**：只能诊断内容，不能评价效果。
- **发了但反馈不足**：说清哪些能判断、哪些不能，最多追问一项最影响结论的信息。
- **有实际反馈**：播放、点赞、涨粉、评论、私信、咨询、成交，以及用户自己的观察。真实的评论和私信内容往往比后台数字更有用。

只有播放数不能判断观众动机。不要求一次补齐所有后台截图。

## 用后台数据先缩小范围

用户手里有后台数据时，先用它判断问题大概出在哪一段，再去看那一段的内容。各平台叫法不一样，意思对得上就行：

| 看到的情况 | 先查哪里 |
|---|---|
| 开头两三秒就划走的人特别多（比用户平时高一截） | 第一句话、第一个画面、封面和开头对不对得上 |
| 开头留得住，看完的人却很少 | 中段：哪里开始讲自己、讲道理、重复，最有用的那句是不是放在了最后 |
| 播放还行，关注的很少 | 有没有给关注的理由；来的人是不是只对这一件事好奇，对这个人没兴趣 |
| 播放、关注都不错，但没人来问、没人买 | 结尾和承接：观众知不知道能找你做什么、去哪找 |
| 评论区在聊别的事（吵架、跑题、问不相干的） | 选题或留白把什么人招来了，见下面第 1 条 |

数据只说明“哪一段出了问题”，不说明“为什么”。拿同一个账号自己的平时水平比，不拿别人的数字比；数据量很小的时候，差一点不算差异。

**爆了也要复盘**。一条爆款招来的人，决定了下一条能不能接住。先看评论区：问得最多的是什么，想拿它干什么，像不像用户想要的人；再按[丹方](../../tslj-series/SKILL.md)“爆了之后，下一条怎么接”定下一条。

## 沿着链条找偏差

把这条视频的链条从头走一遍，找第一个偏掉的环节：

1. **选题招来了谁**：选题划定的人群是不是用户想要的？题材本身有没有自带一群人？（预测比分会招来想拿去赌的人。）
2. **开头承诺了什么**：观众被什么吸引进来？开头的承诺和用户想提供的东西一致吗？
3. **中段展示了什么**：展示的是成品、过程、生活还是忙碌？你展示什么，就吸引什么人（[炉心](core-mind.md)第六条）。
4. **标题给了什么期待**：标题有没有让人产生和正文不一样的预期？
5. **结尾让观众做什么**：结尾指向的行动，和观众实际想找用户解决的事一致吗？有没有给关注的理由？
6. **承接接住了没有**：有人来问，回了吗？用什么方式回？（有人来问却没人回，是最可惜的一环。）

给出一个有证据的主要解释，必要时加一个替代解释，并说怎么区分两者。不要把一条低播放直接归因于标题或时长。

## 三条路：纠偏、顺势而为，或止损

- **纠偏**：回到想要的结果。只改最先偏掉的那一环，比如想要学习者却展示了成品，下一条就把镜头更多留给思路和过程，结尾指向方法。
- **顺势而为**：来的人虽然不是原计划的人，但需求真实、合法，用户也愿意服务，就为他们设计下一条内容或一个合规的交付（交[成丹](../../tslj-monetize/SKILL.md)）。
- **止损**：来的人要的是违法或害人的东西，不接，并调整内容避免继续招来这群人。

怎么选由用户定，但你要给出推荐和理由。对用户说的时候用大白话（“下一条把镜头留给怎么做”“这些想订蛋糕的人也可以顺手接”），不要用“纠偏”“顺势”当小标题。

## 接到下一条

提出一个最小的调整，交总入口选择对应模块（看火 / 开炉 / 回炉 / 收丹；涉及商业目标才进成丹）。也可以顺着真实需求做下一条答疑，前提是用户愿意且能交付。

用户想持续跟踪、或者已经有记录要续写时，再用一段简短记录把这次判断接到下次：本次目标、对应作品、观察的时间段、已有反馈、当前解释、下一条优先改哪一点、准备观察什么。已有记录就续写；未知项写未知，不当成用户必填的作业。

每次优先检验一个因素，尽量保持其他条件不变，便于比较。下次反馈回来再对照这次的判断；如果发布时间、题材、流量来源也变了，就说明不能单独归因。一次变好只是一次观察，不能马上升级成爆款规律。没有后续反馈就保留“待验证”，不反复催数据。

生活记录类内容，看表达是否符合本人的意图，不强加商业指标。不自动要求提高发布频率或模仿热门风格，调整要考虑用户的表达偏好、时间和拍摄条件。
